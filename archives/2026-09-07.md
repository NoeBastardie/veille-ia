## Message publié

Salut à tous :wave:

Deux sujets cette semaine, plutôt complémentaires : un signal réglementaire sur l'agentique côté données perso, et un retour de terrain sur ce qui fait vraiment progresser un agent interne.

:closed_lock_with_key: *IA agentique et données personnelles* — la CNIL et le Conseil de l'IA et du Numérique pointent trois risques concrets : mémoire persistante qui construit des profils hyperpersonnalisés, autonomie qui dilue la responsabilité entre acteurs, et flux de données que l'utilisateur ne peut plus suivre.
Si un agent que vous cadrez a une mémoire ou touche plusieurs services, c'est le moment de documenter ces flux avant qu'on vous le demande formellement.
• Listez les services que touche un agent interne de votre mission et vérifiez si l'utilisateur peut voir ou annuler une action prise en son nom.

:memo: *Retour d'expérience Warp x Anthropic* — leur agent de code progresse en captant le feedback là où le travail se fait déjà (commentaire inline sur une PR) plutôt que via un formulaire séparé ; réécrire les prompts à la main n'a pas tenu à l'échelle.
Transposable à n'importe quel agent interne : la mécanique de collecte du feedback compte plus que son volume.
• Repérez où votre équipe collecte le feedback sur un agent interne et testez de le ramener dans le flux de travail existant plutôt qu'un formulaire à part.

:warning: À prendre avec des pincettes : la note CNIL est exploratoire, sans nouvelle obligation immédiate — elle rappelle que le RGPD s'applique déjà, ce n'est pas un texte contraignant nouveau. Le retour Warp vient d'un seul client Anthropic, avec des chiffres d'usage (10M sessions Claude Code, 40M conversations) mais aucune métrique de performance publiée.

:point_right: Je liste cette semaine les flux de données de l'agent qu'on pilote en interne et je regarde ce qui manque côté transparence.
